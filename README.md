# Worktree

소규모 팀의 작업·마일스톤·일정을 관리하는 Windows 데스크톱 앱입니다. 작업을 트리·칸반·작업 네트워크·간트 차트로 확인합니다.

아래 안내는 **0.26.1 개발 버전** 기준입니다. 기존 정식 배포 0.20.1의 WBS 방식과 저장 구조가 다릅니다.

## 설치 및 실행

[정식 릴리즈](https://github.com/DevPumpkin0113/worktree/releases/latest)에서 Windows x64 설치 프로그램을 받을 수 있습니다. Windows x64와 WebView2가 필요합니다. 앱 설정 → 앱 정보에서 업데이트 확인과 설치를 진행합니다.

## 프로젝트 시작

1. 우측 하단 **+**로 프로젝트 루트 폴더를 선택합니다. 폴더를 앱으로 드롭해도 됩니다.
2. 프로젝트가 없으면 **프로젝트 초기화**에서 이름·데이터 저장 위치·작업 ID 프리픽스·공수 사용 여부를 지정합니다.
3. 기본 저장 위치는 `docs/worktree/`입니다. `docs/my-plan/` 같은 프로젝트 루트 기준 상대 경로도 지정할 수 있습니다. 초기화는 기존 데이터 폴더를 덮어쓰지 않습니다.
4. **작업 추가** 또는 **마일스톤 추가**로 계획을 작성합니다.

프로젝트 하나가 하나의 문서 집합입니다. 하단 탭은 서로 다른 프로젝트를 전환하며, 좌측에는 여러 WBS 파일을 선택하는 탐색기를 두지 않습니다. 프리픽스는 초기화 시 정하고 앱에서 변경할 수 없습니다. 작업은 `W001.md`, 마일스톤은 `MS001.md`처럼 ID로 저장합니다. 제목을 바꿔도 ID·파일명은 유지하며 삭제한 번호는 재사용하지 않습니다.

프로젝트 관리에서 **프로젝트명·공수 사용·작업 유형·공통 라벨**을 수정하고 저장할 수 있습니다. 작업 유형과 라벨은 쉼표로 구분합니다. 사용 중인 작업 유형은 해당 작업의 유형을 먼저 바꾼 뒤 제거하세요. 공통 라벨 목록에서 제거해도 작업에 기록된 라벨은 남습니다. 프로젝트 폴더·데이터 위치·프리픽스·상태 목록은 원래 항목 위치의 비활성 입력으로 표시합니다. 저장 실패·외부 변경 시 초안을 유지하며 **변경 취소**로 최신 유효 설정을 다시 불러옵니다.

## 작업 작성과 확인

- 작업 제목만 필수입니다. 여러 줄 설명, 담당자, 상태, 일정, 공수, 우선순위, 작업 유형, 라벨, 막힘 사유, 참조를 입력할 수 있습니다.
- 참조는 선택 항목이며 텍스트·URL 또는 프로젝트 루트 기준 상대 파일 경로를 기록합니다. 파일을 복사하거나 첨부하지 않으며 현재는 상세에 내용을 표시합니다.
- 생성·수정 시각은 자동으로 기록합니다. 수정 시 생성 시각은 유지합니다. 외부 편집기로 변경한 파일의 시각은 외부 편집 주체가 관리합니다.
- 마일스톤은 제목과 선택 기간으로 작업을 묶습니다. 소속 없는 작업은 트리의 **미지정** 묶음에 표시합니다.
- 검색은 제목·ID·담당자·설명·유형·라벨을 포함합니다. 담당자·상태 필터도 함께 적용합니다.
- 상세의 **수정**에서 변경 후 명시적으로 저장합니다. **삭제**에서는 마일스톤 하위 작업의 유지/삭제와 연결된 선행 참조 해제 여부를 선택합니다. 앱 내 실행 취소는 지원하지 않습니다.
- 편집 중 프로젝트 파일이 외부에서 바뀌면 덮어쓰지 않고 입력을 유지합니다. 초안을 복사한 뒤 취소하고 최신 내용에서 다시 수정하세요.
- 외부 파일 추가·변경·삭제는 자동 갱신되며 수동 새로고침도 지원합니다. 문서 오류는 하단 오류 버튼에서 해당 파일·필드·확인 가능한 원본 행을 확인합니다.

간트는 일 단위 7일·오늘 중앙, 주 단위 월요일 시작 5주·현재 주 중앙으로 처음 표시합니다. 다른 일정은 가로 스크롤로 탐색합니다. 진행률은 일반 작업의 완료/전체 개수 비율이며, 공수 기준 진척도는 별도 지표입니다.

## 데이터와 설정

프로젝트를 이동·공유할 때 루트의 `worktree.json`과 지정된 데이터 폴더를 함께 가져가세요. 저장 규격은 [프로젝트 문서 규격](docs/PROJECT_FORMAT.md)을 참고하세요. 기존 `.wbs` 읽기·변환·파일 연결과 배포 템플릿은 제거했습니다. 이 저장소의 기존 개발 작업 기록은 `docs/worktree/`에 옮겼습니다. CLI는 추후 지원합니다.

앱 설정과 최근 프로젝트·보기 세션은 `%LOCALAPPDATA%/Worktree/`의 `settings.json`, `session.json`에 각각 저장됩니다. 프로젝트 내용은 여기에 저장하지 않습니다. 손상되거나 지원하지 않는 세션은 보존하며, 복구하려면 앱 종료 후 해당 파일을 다른 곳으로 옮겨 보존하고 다시 실행하세요.

앱의 문제 제보는 앱 정보가 채워진 GitHub 작성 화면을 열며 사용자가 확인 후 제출합니다.

프로젝트 관리는 기본적으로 기존 정보 조회 화면을 유지한다. 프로젝트 수정 버튼으로 편집 화면에 진입하며, 저장 성공 또는 변경 취소 시 조회 화면으로 돌아온다. 조회·수정은 같은 기본 정보/작업 규칙 구조와 순서를 공유하며 고정 항목은 별도 영역 없이 원래 위치에서 비활성 입력으로 표시한다. 저장 실패·충돌 시 편집 화면과 초안을 유지한다.
