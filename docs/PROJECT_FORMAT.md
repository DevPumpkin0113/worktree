# 프로젝트 문서 집합 v1

Worktree 0.24.0부터 프로젝트 하나는 하나의 문서 집합이다. 기존 WBS v2와 별개인 새 규격이며 WBS 입력·자동 이전은 지원하지 않는다. 이 저장소의 과거 작업 데이터만 개발 과정에서 새 규격으로 옮겼다. 배포 템플릿은 제공하지 않으며 앱의 프로젝트 초기화로 생성한다. CLI는 미구현이다.

## 파일 구조

```text
프로젝트 루트/
├─ worktree.json
└─ docs/
   └─ worktree/
      ├─ project.json
      ├─ milestones/
      │  └─ MS001.md
      ├─ tasks/
      │  └─ W001.md
      └─ comments/
         └─ W001/
            └─ 12345678-1234-1234-1234-123456789abc.md
```

루트 `worktree.json`은 `{ "dataDirectory": "docs/worktree" }` 형식이다. 저장 위치는 사용자가 지정하는 루트 기준 상대 경로다. 경로 구분자는 `/`이며 절대 경로·상위 이동·symlink/junction을 통한 외부 접근은 허용하지 않는다. 기존 데이터 폴더를 덮어쓰지 않는다. 폴더 전체를 읽어 하나의 프로젝트로 조합하며 각 파일을 별도 문서 탭으로 열지 않는다.

`project.json`은 schemaVersion(1), name, taskPrefix, idSeparator, useEffort, taskTypes, labels, nextTaskNumber, nextMilestoneNumber를 갖는다. 작업 프리픽스는 영문 대문자 1~20자이고 마일스톤용 MS를 제외한다. 앱에서는 초기화 후 고정이다. 기본 유형은 feature·bug·improvement·task·docs·spike·chore이고 라벨은 자유롭게 추가한다. 0.25.0부터 프로젝트 관리에서 이름·공수 사용·유형·공통 라벨을 수정할 수 있다. 사용 중인 유형은 제거를 거부하며 유형명 변경은 새 유형 추가→작업 유형 수정→기존 유형 제거 순서로 진행한다. 공통 라벨 목록 변경은 작업 파일에 기록된 라벨을 바꾸지 않는다. 경로·프리픽스·상태 목록은 비활성으로 표시한다. 저장은 project.json만 변경하며 번호·스키마·확장 필드와 모든 작업 파일을 보존한다.

## 작업 파일

파일명은 작업 ID와 정확하게 일치한다. 프리픽스 뒤 최소 세 자리 양의 정수를 붙이며 작업과 마일스톤 번호는 독립적으로 증가한다. 삭제 후에도 설정의 발급 번호를 유지한다. 외부 파일이 발급 번호보다 크면 최대 번호 다음부터 발급한다.

Markdown 파일은 `---`로 둘러싼 속성 영역과 설명 본문이다. **각 속성 값은 JSON 문법**으로 작성한다. 문자열은 큰따옴표로 감싸고 배열·객체·숫자는 JSON으로 쓴다. 일반 YAML 전체 문법은 지원하지 않는다. 속성 키는 한 번씩 쓰고 값은 한 줄에 작성하며 설명은 본문에 여러 줄로 작성한다.

```markdown
---
schemaVersion: 1
id: "W001"
title: "검색 기능 개선"
status: "todo"
owner: "박대호"
milestone: "MS001"
start: "-"
end: "-"
effort: "-"
dependencies: []
priority: "-"
type: "feature"
labels: ["검색", "ui"]
blockedReason: ""
references: [{"type":"file","value":"docs/spec.md"}]
createdAt: "2026-10-21T00:00:00.000Z"
updatedAt: "2026-10-21T00:00:00.000Z"
---

사용자가 제목으로 작업을 찾을 수 있도록 개선한다.
```

- 필수 속성: schemaVersion·id·title·createdAt·updatedAt. 설명과 참조는 선택 항목이다. 완료 기준은 별도 항목으로 두지 않는다.
- 상태: todo·doing·blocked·done. 우선순위: project.json의 priorities 항목 ID 또는 미지정 `-`.
- 일정은 YYYY-MM-DD 시작/종료 한 쌍 또는 모두 `-`다. 공수는 양수 문자열 또는 `-`다. useEffort가 false여도 값 검증은 유지하고 표시만 숨긴다.
- milestone은 실제 마일스톤 ID 또는 `-`다. dependencies는 정확한 일반 작업 ID 배열이다. 없는 참조·마일스톤 선행·순환을 거부한다. 선행 종료일이 정해졌으면 후행 시작은 그 다음 날 이후다.
- labels는 문자열 배열이다. 프로젝트 설정의 라벨 목록은 제안 목록이고 작업에 새 라벨을 기록할 수 있다.
- blockedReason은 선택 문자열이다. 상태가 바뀌어도 기존 사유를 자동 삭제하지 않는다.
- references는 `{type: "text" | "file", value: string}` 배열이다. file 경로는 프로젝트 루트 기준 상대 경로이며 파일 존재 여부를 강제하지 않는다. 외부 자료는 text로 URL을 적는다. 원본 파일 복사·실행·자동 다운로드는 하지 않는다.
- createdAt·updatedAt은 UTC ISO 8601 시각이다. 앱은 생성 시 둘을 기록하고 수정 시 updatedAt만 갱신한다. 외부 작성자가 시각을 함께 관리한다. 저장 시 미래의 기존 수정 시각을 과거로 되돌리지 않는다.
- 알 수 없는 메타데이터는 해당 작업 수정 시 보존한다. 편집 대상 파일은 속성/본문을 다시 직렬화하고 다른 작업 파일은 변경하지 않는다.

마일스톤 `milestones/MS001.md`는 schemaVersion·id·title·선택 start/end·createdAt·updatedAt을 사용한다. 별도 작업 번호를 배정하지 않으며 UI에서 MS 번호는 숨긴다. 상태·진척도는 하위 작업에서 집계한다. 내부 모델의 group은 집계를 위한 표현일 뿐 저장 유형이 아니다.

## 저장과 복구

프로젝트별 파일의 정확한 내용과 저장 위치를 읽기 스냅샷으로 사용한다. 쓰기 직전 전체 집합이 바뀌었으면 충돌로 중단한다. 새 파일은 기존 파일을 덮어쓰지 않는 방식으로 생성한다. 앱 안의 읽기·저장은 잠금으로 직렬화하며 파일별 임시 파일 동기화 후 교체한다.

여러 파일을 바꾸는 동안 데이터 폴더의 `.worktree-transaction.json`에 이전/이후 내용을 기록한다. 실패 시 이전 파일로 복구하고, 프로세스 중단 시 다음 읽기에서 미완료 저장을 되돌린다. 중단 후 외부 변경이 있으면 이를 덮어쓰지 않고 복구 기록과 파일을 보존한 채 오류를 표시한다. 복구 기록을 임의로 삭제하지 말고 이전/이후 데이터와 실제 파일을 비교해 충돌을 해결해야 한다. 성공하면 기록을 제거한다. 실행 취소·영구 백업 기능은 아니다.

다른 프로그램의 쓰기를 운영체제 수준에서 잠그지는 않는다. 마지막 비교와 교체 사이의 외부 변경 경합 가능성은 남는다. 초기화 도중 데이터 폴더 생성 후 루트 설정 게시가 실패하면 생성한 데이터를 보존하며 자동 삭제하지 않는다.

최대 관리 파일 수는 project.json을 포함해 2,000개, 문서 집합 내용은 합계 UTF-8 16MiB다. Git에서 빈 폴더가 생략된 경우 tasks·milestones는 빈 집합으로 읽고 첫 저장 시 필요한 폴더를 생성한다. tasks·milestones의 `.md`만 읽으며 하위 폴더는 순회하지 않는다. 기타 문서는 관리 대상에 포함하지 않는다. 설정·세션은 프로젝트 본문과 별도다.

프로젝트 관리는 기본적으로 기존 정보 조회 화면을 유지한다. 프로젝트 수정 버튼으로 편집 화면에 진입하며, 저장 성공 또는 변경 취소 시 조회 화면으로 돌아온다. 조회·수정은 같은 기본 정보/작업 규칙 구조와 순서를 공유하며 고정 항목은 별도 영역 없이 원래 위치에서 비활성 입력으로 표시한다. 저장 실패·충돌 시 편집 화면과 초안을 유지한다.


## 프로젝트별 ID 표시 (0.27.0)

project.json의 선택 속성 `idSeparator`는 `none` 또는 `hyphen`이다. 없으면 `none`으로 읽고 다음 프로젝트 설정 저장 시 명시한다. schemaVersion은 1로 유지하는 선택 속성 추가다. 초기화의 작업 규칙 단계와 프로젝트 관리에서 지정할 수 있으며 다른 프로젝트·기기의 앱 설정에 의존하지 않는다. `W001`을 `W-001`로 표시하는 규칙일 뿐 파일명·원본 ID·선행 관계·마일스톤 ID는 바뀌지 않는다. 앱 설정의 기존 idSeparator 값은 프로젝트에 자동 복사하지 않으며 화면에 적용하지 않는다.


## 날짜·시간 표시 및 초기화 작업 규칙 (0.27.0)

선택 속성 dateFormat은 연·월·일 / 일·월·연 / 월·일·연 순서와 `-`·`.`·`/` 구분기호의 9가지 조합 중 하나다. 기본값은 `yyyy-MM-dd`이며 UI에서는 순서와 구분기호를 독립 선택하고 저장은 기존처럼 합성된 dateFormat 문자열을 사용한다. timeFormat은 `24h`(기본), `12h` 중 하나다. 생략 시 기본값으로 읽으며 schemaVersion은 1을 유지한다. 날짜만 있는 일정은 시간대 변환 없이 표시하고 UTC 생성/수정 시각은 실행 기기의 로컬 시간대로 바꿔 선택한 형식으로 표시한다. 시간대 선택·일정에 시각 추가 기능은 포함하지 않는다. 네이티브 날짜 입력의 값과 간트의 짧은 축 눈금은 기존 규칙을 유지한다. 프로젝트 관리에서 이후 수정할 수 있다.

초기화는 기본 정보(이름·루트·데이터 저장 위치), 작업 규칙(ID 접두어·구분자·날짜/시간 형식·작업 유형·공통 라벨·담당자·우선순위·예상 작업 시간), 최종 확인의 3단계다. 저장 위치 오류는 기본 정보로, 접두어·작업 규칙 오류는 작업 규칙으로 돌아가 수정한다. 업무 유형은 하나 이상이고 라벨은 선택이다. 유형·라벨은 쉼표로 구분하며 중복·줄바꿈·NUL을 허용하지 않는다. 최초 생성 시 모든 규칙을 하나의 project.json에 저장하고 최종 확인의 초기화 버튼으로 실행한다.


초기화 저장 위치 UI는 상위 폴더와 새 폴더 이름을 따로 입력한다. 기본값 docs + worktree이며 상위 폴더를 비우면 프로젝트 루트다. 찾아보기는 기존 상위 폴더를 선택하고 루트 기준 상대 경로로 반환한다. 프로젝트 밖·symlink/junction·파일 경로는 거부하며 최종 생성 시 기존 경로 검사를 다시 수행한다. 새 폴더 이름은 경로 구분자를 입력에서 제외한다. 실제 저장 속성은 합성된 dataDirectory 하나로 유지한다. 전체 생성 경로를 미리 표시한다.

접두어 입력은 ASCII 소문자를 대문자로 바꾸고 영문 대문자 1~20자·MS 제외를 검사한다. 숫자·공백·기타 문자는 자동 제거하지 않고 오류로 표시한다. 최종 확인에서 제출하더라도 잘못된 접두어·경로이면 저장 위치 단계로 돌아간다. Rust의 생성 직전 검사도 유지한다. ID 구분자 입력 하단은 미리보기만 표시한다.


## 유형 색상과 뱃지 입력 (0.27.0)

작업 유형 taskTypes와 공통 라벨 labels의 저장 형식은 문자열 배열을 유지한다. 초기화·프로젝트 관리에서는 이름 입력 후 Enter 또는 +로 뱃지를 추가하고 ×로 제거한다. 입력란에서 포커스를 옮길 때에도 유효한 이름은 추가한다. 쉼표로 여러 이름을 한 번에 붙여넣을 수 있으며 중복은 거부한다. 이름의 정확한 문자열을 유형의 식별자로 사용한다. 사용 중인 유형의 ×는 비활성화하고 저장 경계에서도 삭제를 거부한다. 공통 라벨을 제거해도 작업의 labels는 변경하지 않는다.

선택 taskTypeColors는 `{ "feature": "#176b73" }`와 같이 프로젝트에 정의된 유형 이름을 키로 하는 6자리 HEX 색상 맵이다. 속성이 없거나 해당 유형 색상을 지정하지 않으면 기본 7종은 기본 팔레트로, 사용자 유형은 중립 배경으로 표시한다. 색상은 같은 프로젝트의 작업 보드·목록·상세의 유형 뱃지에 적용한다. 초기화에서는 최초 project.json에 함께 기록하고 프로젝트 관리에서 이후 변경할 수 있다. 작업 파일은 변경하지 않으며, 제거한 유형의 색상만 정리한다. schemaVersion은 선택 속성 추가에 따른 1을 유지한다. UI 모델의 commonLabels는 설정의 공통 라벨이며, labels는 작업 편집 제안을 위해 공통+작업 라벨을 합친 목록이다.


기본 팔레트: feature #a2eeef, bug #d73a4a, improvement #f29a4e, task #e3dede, docs #1d76db, spike #d4c5f9, chore #6c757d. 초기화와 저장소 자체 프로젝트에는 기본 팔레트를 명시하며 기존 프로젝트의 사용자 유형·색상은 초기화하지 않는다. 유형 이름은 언어와 무관하게 원문을 표시한다. 뱃지는 기존 모서리 형태와 옅은 유형색 배경을 유지하며 글자색 자동 선택은 보류한다. 라벨은 중립 배경이며 색상 편집 UI가 없다. frontend·backend·api·database·security는 예시 텍스트일 뿐 기본 라벨 데이터가 아니다.

사용자 화면에서 effort는 예상 작업 시간으로 표시한다. 담당자가 실제로 작업할 예상 시간이며 완료까지의 달력 기간과 구분한다. 기존과 동일하게 시간(h) 단위이며 저장 키 effort/useEffort와 시간 가중 진행률 계산은 유지한다.


## 프로젝트 우선순위와 담당자 목록 (개발 버전 0.27.0)

선택 `priorities`는 `[{"id":"high","name":"상"},{"id":"normal","name":"중"},{"id":"low","name":"하"}]`처럼 높음→낮음 순서로 저장한다. 이름과 ID는 각각 고유하며 이름은 1~100자(앞뒤 공백·줄바꿈·쉼표 제외), 최대 100항목이다. ID는 영문·숫자·밑줄로 시작하고 영문·숫자·밑줄·하이픈으로 구성한 1~80자다. 이름·순서를 변경해도 ID는 유지한다. 사용자 추가 ID는 P_와 UUID로 생성한다. 미지정은 배열 항목이 아니며 작업의 priority에 `-`로 저장한다. 새 작업은 미지정으로 시작한다. 사용 중인 항목은 제거할 수 없다. 전체 우선순위를 제거해 미지정만 사용할 수 있다.

설정이 없는 기존 프로젝트는 기존 low/normal/high의 식별자를 유지하며, urgent를 실제 사용하는 경우에만 긴급 항목을 목록에 포함한다. 기존 작업 파일은 변환하지 않고 프로젝트 설정 저장 시 명시적 목록을 기록한다. 우선순위가 생략된 기존 작업의 normal 의미는 유지한다. 이 속성이 있는 프로젝트는 이전 앱의 고정 우선순위 검증과 호환되지 않을 수 있으므로 0.27.0 이상에서 편집한다. schemaVersion 1은 선택 속성 추가에 따라 유지한다.

선택 `assignees`는 프로젝트 담당자 이름의 고유 문자열 배열이다. 미지정 `-`는 목록 항목으로 등록하지 않는다. 작업 편집은 목록에서 선택하며 기존 작업에만 남아 있는 담당자도 현재 선택지로 유지한다. 목록에서 이름을 제거하거나 바꿔도 기존 작업의 owner를 자동 수정하지 않는다. 계정·권한·사용자 인증을 의미하지 않는다.

초기화·프로젝트 관리에서 목록을 편집하고 저장한다. 위쪽이 높고 아래쪽이 낮은 세로 목록에서 손잡이를 드래그해 순서를 변경한다. 단축키는 실제 환경 동작 확인 전까지 화면에서 안내하지 않는다. 저장 실패·외부 변경 충돌 시 초안을 유지하며 기존 스냅샷 비교·복구 규칙을 따른다.

우선순위 색상은 순서와 전체 개수에서 계산하는 표시 정보이며 파일에 저장하지 않는다. 최상위는 빨강·중앙은 노랑·최하위는 초록으로 두 구간을 균등 보간한다. 짝수 개는 두 중앙 항목 사이가 노랑이며 하나뿐이면 빨강, 미지정에는 색상을 적용하지 않는다. 색상 기준은 테마 토큰이고 목록 변경 후 초기화·관리·선택·상세 표시가 같은 계산을 사용한다.

## 프로젝트 재초기화 (0.28.0)

프로젝트명 확인 후 루트 worktree.json과 dataDirectory 폴더 전체를 삭제한다. 폴더 안의 임의 파일·하위 폴더도 삭제 대상이다. 상위 폴더·다른 프로젝트 및 저장 위치 밖의 파일은 제거하지 않는다. 예를 들어 docs/worktree가 데이터 위치라면 docs는 유지한다. 새 생성은 기존 내용을 이전하지 않으며 작업·마일스톤 번호를 1부터 시작한다.

삭제 전 전체 스냅샷을 비교하고 데이터 트리를 따라가지 않는 링크 검사와 읽기 전용 파일 검사를 수행한다. 루트 .worktree-reset.json에 pending 기록을 동기화한 뒤 데이터 폴더를 루트의 고유 .worktree-reset-data-* 내부 data로 이동하고 marker를 제거한다. deleting 기록 교체가 확정되기 전 실패·중단은 폴더 이동과 marker를 복원하며 기존 경로의 외부 변경은 덮어쓰지 않는다. deleting 이후는 임시 위치의 폴더 전체를 삭제하고 실패·중단 시 다음 검색·읽기·저장·생성 또는 초기화 재시도에서 남은 삭제를 완료한다. 삭제 완료 후 기록과 임시 폴더를 제거한다. 원래 데이터 위치의 상위 폴더는 건드리지 않는다.

초기 생성은 기존 폴더를 덮어쓰지 않으며, 파일 보존용 cleared 영수증·폴더 재사용 분기는 제거했다. 복구 기록과 임시 이동 폴더는 Git에서 제외하며 사용자 실행 취소·영구 백업·외부 쓰기의 전역 잠금은 보장하지 않는다. ADR 0021이 0020의 파일별 삭제 정책을 대체한다.

## 댓글 (0.29.0)

댓글은 `comments/원본작업ID/소문자UUID.md`로 저장한다. UUID는 새 댓글 등록 시 생성하며 작업·마일스톤 번호를 소비하지 않는다. 마일스톤도 `comments/MS001/`처럼 원본 ID를 사용한다. 빈 comments·작업별 폴더는 없어도 되며 폴더 내 댓글은 작업별 number 순서로 표시하며 답글은 원댓글 아래 한 단계로 묶는다. 파일 수 2,000개·총 내용 16MiB 제한에 댓글도 포함한다. 댓글 디렉터리의 링크·잘못된 폴더/Markdown 이름은 거부하며 임의의 다른 폴더를 탐색하지 않는다.

```markdown
---
schemaVersion: 1
id: "12345678-1234-1234-1234-123456789abc"
taskId: "W001"
author: "박대호"
createdAt: "2026-10-22T00:00:00.000Z"
updatedAt: "2026-10-22T00:00:00.000Z"
---

검토 의견입니다.
```

속성 한 줄 JSON·본문 Markdown codec은 작업 문서와 동일하다. id·taskId는 파일 경로와 정확히 같아야 하고 대상 작업·마일스톤이 존재해야 한다. author는 공백으로 시작/종료하지 않는 1~40 UTF-16 코드 단위의 한 줄 표시 이름이다. 본문은 공백만인 내용을 금지하며 최대 2,000 UTF-16 코드 단위다. 앱에서는 본문을 문자열로 표시하며 HTML을 실행하지 않는다. createdAt·updatedAt은 밀리초가 있는 UTC ISO 문자열이고 updatedAt은 createdAt보다 빠를 수 없다. 앱의 댓글 수정은 원래 author·createdAt·확장 메타데이터를 유지한다. 외부 작성자는 직접 시각을 관리한다.

등록은 제출 시점의 현재 스냅샷, 수정·삭제는 해당 동작을 열 때의 스냅샷을 기준으로 전체 프로젝트 충돌 검사를 한다. 실패·충돌 시 입력을 유지한다. 새 댓글은 최신 프로젝트가 읽힌 후 재등록할 수 있으며 충돌한 수정·삭제는 취소하고 최신 내용에서 다시 시작한다. 외부에서 삭제된 댓글의 수정 초안은 복사할 수 있게 남기고 저장은 비활성화한다. 저장·복구는 기존 project_write 거래에 포함된다. 작업·마일스톤 삭제 시 삭제하는 대상 ID의 댓글만 함께 제거하고 하위를 유지하면 하위 댓글도 유지한다. 빈 댓글 폴더는 남을 수 있다.

프로젝트와 댓글 문서의 schemaVersion은 각각 1을 유지한다. 기존 프로젝트는 댓글 폴더 없이 그대로 읽으며 변환하지 않는다. 이전 앱은 댓글을 읽지 못하므로 댓글을 사용하는 프로젝트는 0.29.0 이상에서 편집한다. Git 병합은 댓글별 파일 단위로 처리할 수 있지만 앱이 다른 프로세스의 쓰기를 전역 잠그거나 충돌을 자동 병합하지는 않는다.

표시 이름은 프로젝트 설정이 아닌 앱 settings.json의 선택 displayName에 저장한다. schemaVersion 2를 유지하고 기존 설정의 생략 값은 빈 문자열로 읽는다. 비어 있으면 등록을 비활성화하고 앱 설정으로 안내한다. Git 이름 자동 조회·연동·로그인·작성자별 권한은 제공하지 않는다. 표시 이름 변경은 새 댓글에만 적용한다.

### 댓글 번호·답글

number는 작업별 양의 정수이며 #001처럼 최소 세 자리로 표시한다. UUID와 파일명은 유지한다. 새 번호는 삭제된 댓글을 포함한 최대 번호 + 1이다. 같은 작업 안의 중복 번호는 오류다. 번호 없는 기존 댓글은 작성 시각·UUID 순으로 결정적 번호를 계산하고, 해당 작업의 다음 명시적 댓글 저장/삭제에서만 파일에 고정한다. 읽기만으로 파일을 변경하지 않는다.

답글은 rootId(최초 원댓글 UUID)와 replyTo(직접 답한 댓글 UUID)를 모두 기록한다. 같은 작업 안에서 존재하는 더 작은 번호만 가리키며 rootId는 답글이 아닌 원댓글이어야 한다. 답글에 답해도 같은 rootId를 유지하므로 화면은 한 단계만 들여쓴다. 본문 앞에 직접 대상 번호만 메인 색상으로 표시하고 클릭하면 대상으로 이동한다. 접근성 이름에는 대상 번호와 작성자를 포함한다. 새 답글은 삭제되지 않은 대상에만 작성할 수 있다.

댓글 삭제는 deleted: true와 빈 본문으로 저장한다. 번호·연결·원래 작성자·작성 시각은 유지하고 수정 시각을 갱신한다. 살아 있는 답글이 참조하는 삭제 댓글은 ‘삭제된 댓글’로 표시하며 나머지 삭제 댓글은 숨긴다. 삭제된 댓글은 편집·답글 작성이 불가능하고 댓글 개수에서 제외한다. 작업 자체를 삭제할 때는 삭제 표식을 포함한 해당 작업 댓글 파일을 제거한다. Git에서 같은 작업의 서로 다른 댓글 추가를 병합해 번호가 중복되면 사용자가 번호를 정리해야 하며 자동 재번호하지 않는다.

댓글에는 생성 시각만 표시하며 수정 시각은 저장 데이터에 유지한다. rootId 또는 replyTo로 참조하는 답글이 있으면 수정 버튼은 비활성화하고 마우스 호버에만 커스텀 툴팁으로 이유를 안내한다. 저장 경계에서도 거부하며 삭제 표식으로 남은 답글도 수정 제한에 포함한다.


## 상세 탭과 앱 설정 (0.30.0)

작업 탭은 프로젝트 문서에 기록하지 않는다. session.json schemaVersion 2의 tabs 각 항목에 선택 taskTabs(원본 작업/마일스톤 ID의 중복 없는 순서 배열)와 activeTaskTab(그 배열의 ID 또는 null)을 저장한다. 생략 시 빈 배열·홈으로 읽는다. 최대 작업 탭 수는 문서당 2,000개이며 기존 세션 128KiB 한도도 유지한다. 실제 프로젝트에서 사라진 ID는 복원 시 제외한다. 작업 본문·댓글·초안은 세션에 넣지 않는다. 작업 파일·댓글·project.json 규격은 유지한다. settings.json의 schemaVersion 2는 유지하며 detailMode는 sidebar/tabs다. 기존 modal은 탭 보기로 읽고 다음 설정 저장 시 tabs로 기록한다. 원본 JSON을 읽기만으로 다시 쓰지 않는다. 0.30.0 이전 앱은 tabs 값을 지원하지 않는다.
