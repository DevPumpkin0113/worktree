# 한국어 메시지 리소스 분리

- 결정: 프런트엔드 문구는 src/i18n/ko.ts, 네이티브 문구는 src-tauri/src/i18n/ko.rs에서 관리한다. 프런트엔드는 messages.ts 진입점을 사용하고 동적 문구는 타입이 있는 포맷 함수를 사용할 수 있다. JSX·SVG·HTML 마크업은 렌더러에 유지하고 텍스트만 리소스로 옮긴다.
- 이유: 한국어 표시와 현재 동작을 유지하면서 후속 다국어 적용에 필요한 문구 변경 지점을 모은다. 추가 라이브러리 없이 수행할 수 있는 첫 단계다.
- 계약: WBS_COLUMNS와 WBS_SECTION_PATTERN은 domain/wbs-schema.ts의 파일 규격이다. 번역 대상이 아니며 언어와 무관하게 기존 문서를 읽는다. 사용자 문서 내용·경로·입력된 이름은 번역하지 않는다.
- 보류: 언어 선택·설정 저장·날짜 및 숫자 로케일 전환·오류 코드 계약은 이번에 도입하지 않는다. document-errors의 한국어 정규식은 기존 오류 판별 계약이므로 유지하며, 실제 언어 전환 전에 문장 분석을 오류 코드 기반으로 바꿔야 한다. 문자열 조합으로 남은 문구도 추가 언어를 적용할 때 어순·복수형을 검토한다.
- 제외한 대안: WBS 열 이름까지 UI 번역과 공유하면 파일 호환성이 바뀌므로 제외한다. 이번 단계에서 i18n 프레임워크와 언어 설정 UI를 도입하면 승인 범위를 넘어가므로 언어 전환 단계에서 선택한다.

- 후속 범위: 사용자 요청으로 en.ts·en.rs 번역을 준비한다. 한국어를 런타임 기본값으로 유지하고 언어 전환과 오류 코드 계약은 여전히 별도 작업이다.

- 후속 결정: 앱 표시 언어 선택·저장은 0007-app-language-setting.md로 확장한다. 문서 오류 판별은 한국어를 유지하며 전체 오류 번역은 계속 보류한다.
