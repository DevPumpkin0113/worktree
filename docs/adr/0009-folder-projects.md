# 폴더를 기준으로 하는 프로젝트와 세션

- 결정일: 2026-10-21
- 결정: 사용자가 선택한 폴더 하나를 프로젝트로 사용한다. 하단 ProjectDock은 프로젝트별 탭을 표시하고 좌측 ProjectFiles는 내부 WBS를 상대 경로로 나열한다. 현재 선택 WBS가 보드·목록·인사이트의 데이터 기준이다. 별도 프로젝트 파일이나 원본 변경은 없다.
- 이유: 문서 탭마다 프로젝트가 달라지는 구조에서 벗어나 한 폴더의 계획 문서를 묶고 문서별 보기와 마지막 선택을 유지한다. 실제 파일·폴더 선택 및 검색은 Rust 경계에서 수행한다. WBS는 선택한 것과 세션 복원에 필요한 것만 읽는다.
- 탐색: 하위 폴더를 재귀 검색하되 숨김 이름 폴더·node_modules·target·dist와 링크·junction은 제외한다. WBS 2,000개·폴더 10,000개·깊이 64를 넘으면 오류를 표시한다. 검색 실패는 기존 프로젝트를 교체하지 않는다. 새로고침으로 목록을 다시 검색하며 기존 활성 파일 polling은 유지한다. 직접 연 기존 Markdown은 호환 항목으로 보존한다.
- 세션: 0003의 문서별 탭 운영을 프로젝트별 탭으로 대체한다. schemaVersion 2에 projects·activeProjectPath·recentProjects를 추가하고 tabs는 문서별 보기 캐시로 유지한다. recentFiles는 v1 호환 필드로 유지하되 새 저장은 빈 배열이다. v1은 같은 상위 폴더를 묶어 메모리에서 이전하고 다음 정상 저장에 v2로 쓴다. 구버전 앱은 v2를 지원하지 않으며 손상·미지원 세션 원본 보존 정책은 유지한다.
- 제한: 프로젝트·보기 캐시 각 최대 40개, 최근 프로젝트 12개. 각 프로젝트의 선택 문서 캐시를 우선 보존한다. 프로젝트 닫기는 원본 폴더나 파일을 삭제하지 않는다. 중첩 폴더를 별도로 열면 별도 프로젝트로 취급한다. 파일 연결·파일 드롭은 파일의 상위 폴더를 루트로 사용한다.
- 제외한 대안: 파일별 탭은 폴더 묶음 요구를 만족하지 못한다. 프로젝트 설정 파일 도입은 아직 저장할 프로젝트 설정이 없으므로 보류한다. 모든 WBS를 병합한 집계는 ID 충돌·규격 결정이 필요하므로 이번 범위에서 제외한다.
