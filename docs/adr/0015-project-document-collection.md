# 0015. 프로젝트별 문서 집합

- 상태: 확정 (2026-10-21, 박대호 결정)
- 대체: 0009의 다중 WBS 탐색 단위, 0010의 표 셀 저장 형식, 0012의 WBS v2 단일 입력 규격
- 유지: 마일스톤 묶음·일반 작업 선행 관계·명시적 삭제 선택·외부 변경 충돌 보호·프로젝트 탭과 보기 상태

## 결정

프로젝트 하나에 문서 집합 하나를 둔다. 루트 worktree.json이 기본 docs/worktree 또는 사용자 지정 상대 경로를 가리킨다. 데이터 폴더에는 project.json, tasks/프리픽스번호.md, milestones/MS번호.md를 둔다. 사용자 지정 작업 프리픽스는 초기화 시 지정하고 변경 UI는 보류한다. 제목 변경은 ID와 파일명을 바꾸지 않는다.

설명은 선택 Markdown 본문으로 통합한다. 우선순위·작업 유형·라벨·막힘 사유·선택 참조·생성/수정 시각은 작업별 속성으로 저장한다. 속성은 한 줄 JSON 값을 쓰는 제한된 front matter다. 다중 파일 저장에는 충돌 검사·동기화된 임시 파일·복구 기록을 적용한다. CLI는 추후 같은 규격을 사용하도록 설계하되 이번에는 구현하지 않는다.

## 이유

표 셀의 한 줄 제약을 없애고 작업별 Git 변경 이력과 AI 협업을 지원한다. 같은 프로젝트의 작업을 여러 WBS에 나누는 화면과 관계 규칙을 줄인다. 앱 초기화가 실제 파일을 만들기 때문에 배포 템플릿을 유지할 필요가 없다.

## 제외한 대안

- WBS 한 파일에 열 추가: 설명·참조 확장이 어렵고 서로 다른 작업의 수정이 같은 파일에 집중된다.
- 프로젝트 안의 여러 독립 계획: 계획 간 관계·집계·이동 규칙이 현재 범위에 불필요하다.
- DB만을 원본으로 사용: 사람이 읽는 파일과 Git 기반 기록이라는 현재 방향에 맞지 않는다.
- 일반 YAML 전체 지원: 현재 필요한 문자열·배열·구조화 참조에는 한 줄 JSON 값으로 충분하다. 규격을 문서화해 CLI에서 재사용한다.

## 영향

이전 WBS 입력·자동 이전·OS WBS 파일 연결과 프로젝트 내부 예제·배포 템플릿을 제거한다. 이 저장소의 개발 작업 데이터는 새 형식으로 옮겨 이력을 보존한다. 기존 ADR은 과거 결정으로 남긴다. 읽기/쓰기 기술 검증과 실제 WebView2 사용자 인수는 구분한다.
