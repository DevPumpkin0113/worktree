# 0017 프로젝트 날짜·시간 표시와 초기화 규칙

- 상태: 확정
- 날짜: 2026-10-21

## 결정

project.json의 선택 dateFormat(연월일/일월연/월일연과 -·.·/의 9가지 조합)·timeFormat(24h, 12h)을 프로젝트 초기화와 관리에서 지정한다. 생략 시 yyyy-MM-dd·24h다. 일정은 기존 날짜, 생성·수정은 UTC 시각으로 저장한다. 표시 시에만 형식을 적용하며 시각의 시간대는 실행 기기 로컬이다. 초기화에 업무 유형·공통 라벨·공수 사용을 지정하는 작업 규칙 단계를 추가한다. schemaVersion은 선택 속성을 추가하는 1을 유지한다.

## 이유

팀의 날짜·번호·작업 분류 규칙을 프로젝트 문서로 함께 관리한다. 초기화에서 기본 작업 규칙을 지정해 생성 후 설정을 다시 수정하는 단계를 줄인다. 날짜만 있는 일정을 시간대 변환해 하루가 바뀌는 문제를 피한다.

## 제외한 대안

- 표시 형식으로 원본 날짜·시각을 저장: 파싱·정렬·일정 계산과 CLI 재사용을 어렵게 한다.
- 앱 설정에 표시 형식 저장: 프로젝트별 규칙이 사용자 설정에 따라 달라진다.
- 기본 보기 추가: 이번 사용자 범위에서 제외했다.

## 영향

작업 목록·마일스톤·상세 기간·간트 접근성 설명과 생성/수정 시각에 공용 포맷을 적용한다. 간트의 짧은 눈금과 네이티브 날짜 입력은 목적에 맞는 기존 형식을 유지한다. 시간대 설정과 일정의 시각 입력은 구현하지 않는다. 원본 시각을 툴팁으로 유지한다.

날짜 UI는 순서와 구분기호를 분리해 선택한다. 두 선택 중 하나를 바꿔도 다른 선택과 시간 형식은 유지한다. 저장 속성은 합성한 dateFormat 문자열 하나로 유지하므로 기존 네 가지 값의 읽기·표시도 바뀌지 않는다.
