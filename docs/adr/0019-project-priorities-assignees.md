# 0019 프로젝트 우선순위와 담당자 목록

- 상태: 확정
- 날짜: 2026-10-22

## 결정

프로젝트 설정에 선택 priorities 배열({id,name})과 assignees 문자열 배열을 저장한다. 우선순위 배열은 높음→낮음 순서이며 ID는 생성 후 유지한다. 초기 기본값은 상·중·하, 미지정은 목록 밖의 `-`다. 새 작업의 기본 우선순위는 미지정이다. 사용 중인 우선순위는 제거하지 못하며 이름·순서는 변경 가능하다. 드래그 손잡이와 Alt+↑/↓를 제공한다.

담당자는 이름 목록에서 선택하며 목록에서 제거해도 기존 작업의 owner를 유지한다. 편집 시 기존 담당자를 선택지에 포함한다. 계정·인증은 도입하지 않는다.

## 이유

팀별 용어와 단계 수를 조정하면서 기존 작업의 연결을 보존한다. 별도 rank 숫자 대신 배열 순서를 사용해 드래그 결과와 저장 데이터가 일치한다. 초기화·관리 편집의 동일 목록 UI와 기존 안전 저장 구조를 재사용한다.

## 제외한 대안

- 우선순위 이름을 작업의 참조 키로 사용: 이름을 바꿀 때 전체 작업을 변경해야 한다.
- 고정 enum 유지: 사용자 지정 단계와 정렬을 지원하지 못한다.
- 담당자 삭제 시 작업에서 이름도 제거: 이전 책임 기록을 잃는다.

## 영향

schemaVersion 1은 유지하며 새 선택 속성을 저장한다. 기존 작업 파일은 변경하지 않는다. 기존 우선순위 식별자를 유지하고 사용 중인 urgent만 기존 프로젝트 목록에 남긴다. 새 프로젝트는 세 단계다. 이전 앱의 고정 enum 검증은 사용자 우선순위를 읽지 못할 수 있어 편집은 0.27.0 이상이 필요하다. 저장 실패·충돌 초안 보존 및 프로젝트 전체 스냅샷 비교는 유지한다.

우선순위 표시는 현재 배열 순서·개수에 따라 테마 빨강→노랑→초록을 보간한다. 색상을 각 항목에 저장하거나 직접 편집하지 않는다. 미지정은 색상 표시에서 제외한다.
