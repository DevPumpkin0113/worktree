# 0021. 데이터 저장 폴더 전체 초기화

- 상태: 확정 (2026-10-22, 박대호 요청)
- 대체: 0020의 관리 파일만 삭제·일반 파일 보존·cleared 영수증 기반 폴더 재사용
- 유지: 정확한 프로젝트명 확인·스냅샷 충돌 검사·프로젝트별 캐시 분리

## 결정

데이터 저장 위치는 초기화의 삭제 경계다. 루트 worktree.json과 데이터 폴더 및 그 안의 모든 파일·하위 폴더를 제거한다. docs/worktree라면 worktree만 제거하고 docs와 저장 위치 밖의 파일은 유지한다. 모달에서 해당 전체 삭제 범위를 안내한다. 새 생성 단계에서 저장 위치와 작업 규칙을 다시 선택한다.

데이터 트리는 링크를 따라가지 않으며 링크·읽기 전용 파일을 사전에 거부한다. 스냅샷 비교 후 루트 .worktree-reset-data-*의 data로 폴더를 이동하고 marker를 제거한다. pending 중단은 폴더와 marker를 복원한다. deleting 기록 교체를 확정점으로 하며 이후에는 잔여 삭제를 재시도한다. 완료 시 기록과 임시 폴더를 제거한다. 상위 폴더 정리·영구 백업·사용자 실행 취소는 제공하지 않는다.

## 이유

사용자가 개별 관리 파일 삭제 대신 데이터 저장 폴더 자체를 제거하고 상위 폴더는 유지하도록 선택했다. 폴더 전체의 삭제·다시 생성이라는 동작을 일관되게 제공하고, 삭제 시작 전 이동 실패와 실제 삭제 도중 중단을 구분해 처리한다.

## 제외한 대안

- 관리 파일만 삭제: 초기화 후 데이터 폴더와 임의 파일이 남아 사용자가 선택한 범위와 다르다.
- 원래 위치에서 즉시 재귀 삭제: 도중 중단 시 부분적으로 삭제된 프로젝트가 정상 설정처럼 남는다.
- 상위 docs까지 삭제: 선택한 데이터 저장 위치 밖의 문서를 건드린다.

## 검증

이번 수정은 사용자가 직접 테스트하기로 요청했다. 이전 방식의 초기화 테스트 코드를 제거했으며 자동 검사·실제 삭제 검증은 실행하지 않았다. 기존 방식의 통과 기록을 이 결정의 검증 결과로 사용하지 않는다.
