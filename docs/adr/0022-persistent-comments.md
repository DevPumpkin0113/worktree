# 0022. 댓글별 문서와 앱 표시 이름

- 상태: 확정 (2026-10-22, 박대호 결정)
- 연결: 0015 문서 집합·0010 저장 충돌 보호 유지. 임시 댓글 UI의 메모리 전용 저장을 대체.

## 결정

댓글을 데이터 위치의 comments/원본작업ID/UUID.md에 하나씩 저장한다. 작업과 마일스톤 모두 사용하며 author·createdAt·updatedAt·본문을 기록한다. 원본 작업 ID와 댓글 UUID는 고정이다. 앱 설정 일반의 displayName을 새 댓글 작성자로 사용하며 Git 사용자 이름을 조회하거나 제안하지 않는다. 기존 댓글의 작성자·작성 시각은 이름 변경이나 댓글 수정으로 바꾸지 않는다.

표시 이름은 앱 settings.json(schemaVersion 2)에 선택 문자열로 추가하며 기본은 비어 있다. 이름 1~40자·본문 1~2,000자(공백만 금지)를 저장 경계에서 검사한다. 새 댓글의 스냅샷은 제출 시 고정하고 수정·삭제는 시작 시 고정한다. 기존 전체 스냅샷 비교와 임시 파일 교체·복구를 재사용하며 실패·충돌 시 입력을 유지한다. 댓글은 파일 수·내용 제한에 포함하고 작업 삭제 시 해당 댓글도 삭제한다. 프로젝트 schemaVersion 1은 유지한다.

## 이유

작업 정보와 대화를 분리하면서 Git에서 서로 다른 댓글 추가의 충돌을 줄인다. 앱 표시 이름은 Git 설치나 저장소 설정에 의존하지 않고 사용자가 실제 댓글의 이름을 직접 확인할 수 있다. 로그인·실시간 서버 협업 없이 현재 파일 기반 구조에서 동작한다.

## 제외한 대안

- Git 이름 사용·초기 제안: 사용자가 앱 표시 이름만 사용하도록 선택했다.
- 작업 파일 본문에 댓글 추가: 설명 편집과 대화 추가가 같은 파일에서 충돌한다.
- 작업별 댓글 파일 하나: 같은 작업에 댓글을 추가할 때 Git에서 같은 파일을 편집한다.
- 앱 설정·DB에 댓글 저장: 프로젝트 이동·Git 관리 및 외부 도구 편집과 분리된다.
- 이름 기반 수정 권한: 표시 이름은 인증된 계정이 아니므로 권한 근거로 사용하지 않는다.
