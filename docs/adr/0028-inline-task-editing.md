# 0028. 작업·마일스톤의 상세 편집과 작성 탭

- 상태: 확정 (2026-10-22, 박대호 결정)
- 연결: ADR 0024·0025의 탭/우측 패널과 세션 복원 정책은 유지한다.

## 결정

기존 항목의 수정은 상세 내부 편집으로 전환한다. 상단 식별 정보·제목과 하단 저장·취소를 유지하고 가운데 폼만 스크롤한다. 생성은 새 작업·새 마일스톤 콘텐츠 탭을 사용하며 같은 편집 필드·검증·스냅샷 저장을 재사용한다. 여러 작성 탭을 열 수 있고 저장 시 ID를 배정해 같은 탭 위치를 상세로 교체한다. 앱의 상세 방식 설정은 유지하면서 해당 프로젝트만 탭으로 표시한다. 작성 초안과 작성 탭은 현재 창에서만 유지하고 세션 파일에 저장하지 않는다. 생성은 유효한 외부 갱신을 반영한 스냅샷을 제출 시 고정하고 기존 항목 수정은 편집 시작 스냅샷을 유지한다.

기존 항목은 편집 시작 시 프로젝트 스냅샷을 고정하고 polling을 유지한다. 저장 실패·충돌은 초안과 오류를 보존한다. 작업·프로젝트 전환 시 편집 컴포넌트의 상태를 유지하되 비활성 폼 DOM은 렌더링하지 않는다. 프로젝트 닫기·초기화·앱 종료 시 편집 초안을 해제하며 디스크 세션에는 저장하지 않는다. 저장·취소 후 기존 상세 조회로 복귀한다.

## 이유

상세와 수정 모달 사이를 오가는 부담을 줄이고 탭·분할 화면 안에서 작업을 마친다. 생성과 수정의 도메인 규칙을 분리하지 않아 향후 CLI와 저장 규격을 공유할 수 있다.

## 제외한 대안

- 수정 모달 유지: 상세와 입력 화면의 문맥이 분리된다.
- 입력마다 자동 저장: 명시적 저장·취소와 충돌 시 초안 보존 정책이 달라진다.
- 전환마다 초안 초기화 또는 디스크 저장: 잠깐의 탐색에서 입력이 사라지거나 프로젝트 내용의 별도 복사본이 생긴다.
