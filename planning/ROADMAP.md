# Worktree 후속 검토

기준: 0.4.0 / 2026-10-20. 아래 항목은 코드와 현재 검증 범위에 따른 후보이며 추가 구현을 확정한 계획이 아니다.

## 1차 목표 평가

WBS 파일 열기, 네 가지 시각화, 검색·상태 필터, 상세 탐색, 모달·사이드 패널 전환과 원본 변경 읽기를 갖췄다. 사용자 확인에 따라 읽기·시각화 도구의 1차 목표는 완료로 본다. 설치 후 전체 동작·키보드 접근성·대량 문서의 성능까지 검증된 상태는 아니다.

## 우선 보완 후보

1. 문서 오류 안내: 현재 오류는 ID·규칙 중심이다. 오류 행·열과 수정 예시를 제시하면 형식이 엄격한 양식 작성이 쉬워진다.
2. 화면 상태 유지: 원본이 갱신되면 load가 상세와 그래프 선택을 초기화한다. 선택 작업이 남아 있다면 유지하고 스크롤·접힘 상태도 보존하는 개선을 검토한다.
3. 최근 파일·세션 복원: 현재 열린 문서는 메모리에서 관리한다. 재실행 시 파일·보기·선택 작업을 다시 찾는 비용을 줄일 수 있다. 사라진 파일과 권한 오류도 처리해야 한다.
4. 긴 문서 사용성: 작업 수가 많은 실제 WBS로 검색·그래프·간트의 렌더링과 키보드 이동을 검증한다. 측정 전 가상화나 복잡한 최적화를 도입하지 않는다.
5. 규격 일치: 공용 문서는 그룹 일정·공수의 하위 집계를 설명하지만 현재 앱은 그룹 상태만 집계한다. 그룹 상세의 일정·공수 요약과 미정 포함 표기를 후속 검토한다.
6. Windows 회귀 확인: 새 설치·업데이트·파일 연결, 파일 삭제·이름 변경·읽기 실패, 최소 크기·배율·모달 및 패널 동작을 실제 앱에서 확인한다.

출력·공유(PDF/이미지), 그래프 확대·화면 맞춤은 사용 중 필요가 확인되면 추가한다. 현재 필수 범위로 두지 않는다.

## 작성·수정 기능: 후속 단계

처음부터 전체 Markdown 편집기를 만들기보다 기존 상세에서 상태·담당자·일정을 수정하는 흐름부터 검토한다. 그 다음 작업 추가·삭제와 계층·선행 관계 편집으로 확장한다.

편집 구현 전 다음을 설계한다.

- 기존 문서의 설명·메타데이터·표 순서·서식을 보존할 수 있는 저장 방식.
- 원본의 외부 변경을 감지하고 덮어쓰기 충돌을 안내하는 방식.
- 저장 전 규격 검사, 안전한 파일 교체·복구와 실행 취소.
- ID 생성·참조 갱신과 삭제 시 연결 작업 처리.
- 자동 저장과 명시적 저장의 선택 및 미저장 변경 표시.

읽기 파서는 원문을 보존하는 편집기가 아니다. 읽어낸 데이터로 문서 전체를 다시 쓰는 방식은 먼저 도입하지 않는다.
