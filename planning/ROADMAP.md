# Worktree 로드맵

기준: 정식 0.13.0 / 개발 0.19.0(미배포) / 2026-10-21

박대호가 R01~R06의 순차 진행을 선택했다. R05의 접근성·대량 문서 검증은 추후로 보류하므로 현재 실행 순서는 **R01→R02→R03→R04→R06**이다. R07~R09 중 안전한 저장과 작업 수정·추가를 이번 범위로 선택했으며, 나머지 범위와 R10~R15는 후보로 유지한다. 작업은 develop에서 직접 수행하고 기능별 검증 및 명시적 커밋 승인 후 별도 커밋으로 관리한다.

## 현재 위치와 방향

문서 열기, 트리·칸반·작업 네트워크·간트 차트, 검색·상태 필터, 상세 탐색과 외부 변경 읽기를 구현했다. 읽기·시각화 도구의 1차 목표는 완료했다. Windows 전체 조작·접근성·대량 문서 성능은 추가 검증이 필요하다.

Jira와 비교하면 가장 큰 차이는 작업을 조회하는 기능에 비해 작성·수정, 작업 맥락과 변경 기록, 검토·승인, 목표·우선순위 관리가 부족하다는 점이다. Jira의 모든 기능을 복제하기보다 **로컬 .wbs 파일을 codex가 작성하고 박대호가 빠르게 확인하는 흐름**을 유지한다.

## 현재 구현·확인 상태

- 0.5.0: 상태 표시줄·오류 하단 패널·전체 설정 화면, 실제 빌드 정보·업데이트 확인/설치·문제 제보 연결을 배포했다. UI만 구성한 단계는 종료됐다.
- 0.5.1: 개인 개발자 식별자와 별도 JSON 설정 저장을 배포했다. 박대호가 설치·기존 설정 이전·재실행·파일 연결 확인을 완료했다.
- R01: 0.6.0 개발 버전에서 오류 셀의 원본 행·문자 열 범위와 수정 예시를 구현했다. 정확한 열을 모르면 행만 유지한다. 자동 검증 완료. 박대호의 기능별 커밋 일괄 승인에 따라 R01 커밋 완료. 실제 앱 확인은 별도다.
- R05: 박대호가 0.5.2 실제 앱 확인 완료를 알렸다. 전체 접근성·배율·키보드·대량 문서 검증은 추후로 보류했다.
- R02: 같은 문서 갱신 시 상세·보기별 스크롤·그룹 접힘 복원 구현 및 자동 검증 완료. 문서 전환은 상세를 닫고 삭제된 작업의 선택을 해제한다.
- R03: 최근 파일 12개·열린 탭 최대 40개와 문서별 보기·간트 단위 복원 구현. 누락 파일은 건너뛰고 오류와 최근 목록을 유지한다.
- R04: 담당자·미정 필터 구현. 검색·상태 조건과 함께 적용하며 문서 전환 또는 담당자 삭제 시 전체 담당자로 복귀한다. 목표 필터는 R11 이후 후보로 유지한다.
- R06: 트리 그룹 요약과 그룹 상세에서 말단 일정·공수·진척도를 집계한다. 미정 값과 마일스톤을 구분하고 필터와 무관한 전체 그룹 집계를 표시한다. 작성/수정 기능은 미선택 후보로 유지한다.

## 선택할 때 확인할 내용

### 읽기·탐색 보완 — R01~R06

현재 문서 형식을 크게 바꾸지 않고 사용 편의를 높이는 후보들이다. 담당자 필터는 현행 WBS 데이터만으로 시작할 수 있다. 최근 파일 목록과 전체 세션 복원은 별도 작업으로 나눌 수 있다.

원본 갱신 후 상태 복원은 작업 삭제·ID 변경·필터 변경 상황을 함께 다룬다. 성능 개선은 먼저 측정하고, 필요가 확인된 부분에만 최적화를 적용한다.

### 작성·수정 — R07~R09

전체 Markdown 편집기보다 상태·담당자·일정을 수정하는 작은 범위부터 검토한다. R08과 R09 중 먼저 선택한 기능이 있어도 **R07의 저장 기반을 먼저 확보**해야 한다.

- 설명·메타데이터·표 순서·서식을 보존한다. 현재 읽기 파서의 결과로 문서 전체를 다시 쓰지 않는다.
- 외부 편집과 충돌하면 덮어쓰기 전에 감지한다.
- 저장 전 규격 검사, 안전한 파일 교체·복구와 실행 취소 범위를 정한다.
- 자동 저장·명시적 저장과 미저장 표시 방식을 결정한다.
- 작업 추가·삭제 시 ID 중복·부모·선행 참조와 연결 작업의 영향을 처리한다.

### 작업 관리 — R10~R13

단순 필드 추가 전에 .wbs에서 정보를 보관할 위치와 기존 문서 호환성을 결정한다. 앱 버전과 schema_version은 별개로 관리한다.

R12에서는 `done`이 구현 완료인지 인수 완료인지 명확히 한다. 개발 상태와 검토 상태를 분리하는 방안을 먼저 검토하며, codex의 기술 검증 통과만으로 박대호의 승인을 기록하지 않는다. 로그인·권한이 없는 로컬 앱의 승인 표기는 협업 기록이며 접근 통제를 보장하지 않는다.

R13에서는 앱에서 한 변경과 외부 편집기·에이전트가 수정한 변경 중 어디까지 추적할지 결정한다. 기존 Git 기록의 활용과 별도 로그 저장을 비교하고 원본에 기록이 계속 누적되는 방식은 먼저 확정하지 않는다.

### 일정·진행 파악 — R14~R15

자동 일정 조정보다 경고와 요약부터 검토한다. 경고는 미정 날짜를 지연으로 취급하지 않고 완료 작업을 구분한다. 목표별 진척도는 작업 개수와 예상 공수의 의미를 구별하고 미정 값을 추정하지 않는다.

현재 날짜 규격은 선행 종료 다음 날 착수하는 FS 관계다. 당일 인계·시간 단위·자동 일정 조정은 별도 규격 검토가 필요한 확장 후보다.

## 현재 우선 범위 밖의 후보

필요가 생기면 다시 검토하되 이번 구현 목록에 자동 포함하지 않는다.

- 출력·공유: PDF·이미지 내보내기.
- 차트 탐색: 확대·축소·화면 맞춤.
- 협업 서비스: 댓글·첨부, 실시간 동기화, 계정·권한·알림.
- 고급 운영: 스프린트·번다운·작업량 통계, 사용자 정의 워크플로·자동화.
- 외부 연동: Jira·GitHub 작업과의 동기화.

## 작업 순서 결정 기록

현재 상태: **R01·R02·R03·R04·R06 구현·자동 및 브라우저 기술 검증 완료. 박대호의 일괄 승인에 따라 develop에서 기능별로 커밋한다. 개발 버전은 0.13.0이며 실제 설치 앱 인수·푸시·main 병합·배포는 별도다. R05는 보류한다.**

선택할 때 다음 네 가지를 정한다.

1. 목표: 이번 develop에서 어떤 사용 흐름까지 완성할지.
2. 범위·순서: R 번호와 먼저 구현할 최소 범위. 필요한 선행 항목 포함.
3. 완료 기준: codex의 기술 검증과 박대호의 실사용 확인을 각각 지정.
4. 배포 조건: main에 병합할 목표 수준. 버전과 일정은 범위 확정 후 지정.

박대호가 목표·우선순위·승인을 결정하고, codex는 구현 범위·의존 관계·검증 방안을 구체화한다. 확정 항목은 Worktree.wbs에 담당자·상태·일정·선행 관계를 추가한 뒤 develop에서 직접 작업한다. 일정이 정해지지 않은 작업은 날짜를 미정으로 둔다. 미선택 후보는 todo 작업으로 일괄 등록하거나 임의 일정·버전을 부여하지 않는다.

현재 WBS의 UI·Windows 검증 일정은 기존 검토 초안이다. R05 보류 지시에 따라 해당 검증의 확정 일정으로 사용하지 않는다.

박대호가 임시 댓글 UI와 고정 탭·스크롤바 조정을 확인하고 develop 병합을 승인했다. UI 시안은 채택하며 실제 저장 형식·작성자 식별·변경 이력 방식은 아직 미확정이다. R10·R12·R13 구현 완료로 간주하지 않는다. 다음 설계에서는 문서 연결 방식과 댓글 저장·외부 편집 충돌 처리부터 결정한다.

## 0.15.0 프런트엔드 구조 전환

0.14.2 UI를 커밋한 뒤 React·TypeScript로 기존 동작을 이관한다. Vite·npm·Tauri·Rust는 유지한다. 새 제품 기능·프로젝트 저장·서버·MCP·CLI는 범위 밖이며 사용자 화면 확인과 커밋 승인은 별도다.

## 0.18.0 폴더 프로젝트

폴더별 프로젝트 탭과 내부 WBS 선택·세션 이전을 구현했다. 보드·목록·인사이트는 선택 WBS 기준이며 여러 문서의 통합 집계·프로젝트 설정 파일은 후속 설계 대상이다. 사용자 화면 확인과 커밋은 별도다.

## 0.19.0 작업 수정·추가 선택

박대호가 작업 수정·추가부터 진행하도록 선택했다. R07의 원문 보존·내용 비교·임시 파일 교체, R08의 필드 수정과 R09의 task/milestone 추가를 구현한다. 그룹 생성·삭제·ID/유형 변경·문서 생성·영구 백업·실행 취소는 남은 후보이며 R07~R09 전체 완료로 간주하지 않는다. 사용자 실제 앱 확인과 새 소스 커밋은 별도다.

## 마일스톤 규격 전환 (0.20.0)

ADR 0011에 따라 최상위 묶음을 마일스톤으로 전환하고 날짜형 항목은 일반 작업으로 통합했다. R09의 현행 생성 기능은 task와 빈 상태를 허용하는 milestone이며, 위의 날짜형 milestone·빈 그룹 제외 설명은 당시 구현 기록이다. 프로젝트 내부 작성 양식과 예제는 WBS v2를 기준으로 한다.
