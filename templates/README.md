# WBS 작성 규칙

이 폴더는 Worktree 프로젝트의 배포용 양식입니다. 현재 문서 규격은 `schema_version: 2`이며 Worktree 0.22.0 이상을 기준으로 합니다. 프로젝트 외부 공용 양식은 이번 변경에 포함하지 않았습니다.

## 사용 방법

[template.wbs](template.wbs)를 `프로젝트명.wbs`로 복사하고 메타데이터·제목·예시 작업을 교체합니다. 내용은 Markdown이며 일반 텍스트 편집기로 수정할 수 있습니다.

- `작업 목록` 바로 아래 첫 연속 표가 원본입니다. 열 이름과 순서를 유지합니다.
- 한 행에 한 항목을 작성하고 빈 값은 `-`, 셀 안의 파이프는 `&#124;`로 씁니다.
- title·project_id·updated를 실제 값으로 교체합니다. 날짜는 YYYY-MM-DD입니다.

## 유형과 ID

| 유형 | 역할 | 상태 | 필수 내용 |
|---|---|---|---|
| milestone | 최상위에서 하위 작업을 묶는 목표 | auto | 제목 |
| task | 실제 수행하는 일반 작업 | todo·doing·blocked·done | 제목·완료 기준 |

- 마일스톤은 제목과 선택 기간으로 생성하며 빈 마일스톤도 허용합니다. 승인·출시 등의 개별 수행 항목은 일반 작업으로 작성합니다.
- 새 마일스톤은 MS001부터 별도 내부 번호를 쓰며 UI에는 번호를 표시하지 않습니다. 일반 작업은 W001 또는 id_prefix의 접두어와 세 자리 이상 번호를 사용합니다.
- `id_prefix: OBS`이면 OBS001·OBS-001 및 기존 W001·W-001을 읽습니다. 마일스톤에는 MS 접두어도 허용합니다. 마일스톤 ID도 문서 내에서 고유해야 합니다.
- 원본 ID는 문서 안에서 고유해야 합니다. 이름 변경·이동 시 유지하며 실제 ID를 변경하면 상위·선행 참조도 함께 수정합니다.
- ID 구분자 설정은 표시만 바꾸며 원본을 변경하지 않습니다. 같은 표시가 되는 작업은 원본 ID를 병기합니다.
- 계층은 번호가 아닌 상위 ID로 결정합니다. 일반 작업의 상위 ID에 마일스톤 ID를 적고 최상위는 `-`로 둡니다. 형제는 원문 순서입니다.
- group 유형은 지원하지 않습니다. 마일스톤은 최상위에만 두며 중첩하지 않습니다.

## 일정과 관계

- 날짜는 시작일·종료일을 포함하는 달력 날짜입니다. 미정이면 둘 다 `-`, 입력하면 둘 다 작성하고 시작일 ≤ 종료일이어야 합니다.
- 마일스톤의 기간은 선택 목표 기간입니다. 하루로 제한하지 않으며 하위 작업 일정 집계와 별도로 표시합니다.
- 마일스톤의 상위 ID·공수·선행 작업·담당자는 `-`, 상태는 auto로 작성합니다. 완료 기준은 선택이며 없으면 `-`입니다.
- 선행 작업에는 일반 task ID만 지정합니다. 여러 개면 쉼표로 구분하고 없으면 `-`입니다. 마일스톤은 지정할 수 없습니다.
- 선행 작업 완료 후 시작(FS), 지연일 0이며 후속 시작일은 선행 종료일 다음 날 이후입니다. 없는 ID·자기 참조·순환 관계는 허용하지 않습니다.
- 담당자는 한 명이며 미정은 `-`입니다. blocked 작업의 원인·해소 조건은 이슈 및 결정 사항에 기록합니다.

## 집계와 공수

- 일반 작업의 완료 개수 / 전체 개수가 진행률입니다. 마일스톤은 작업 수에서 제외하며 중복 집계하지 않습니다.
- 마일스톤 상태는 하위 말단 작업에서 계산합니다. 빈 상태는 todo, 모두 done이면 done, blocked가 있으면 blocked, 모두 todo이면 todo, 나머지는 doing입니다.
- 하위 일정은 최소 시작일~최대 종료일이며 미정이 있으면 함께 표시합니다. 필터를 적용해도 전체 하위 작업으로 집계합니다.
- task 공수는 0보다 큰 총 인시 또는 미정 `-`입니다. milestone 공수는 `-`입니다.
- 공수 기준 진척도는 완료 task 예상 공수 합 / 전체 task 예상 공수 합입니다. 미정 공수가 있거나 합이 0이면 산정 불가이며 작업 개수 진행률과 별개입니다.
- 메타데이터 `use_effort: false`는 공수 UI만 숨깁니다. 생략은 true이며 열과 검증은 유지합니다.

## 문서 규격

`schema_version: 2`를 반드시 명시합니다. v1·규격 누락·group·날짜형 milestone은 지원하지 않고 자동 변환도 하지 않습니다. 기존 파일이 필요하면 현재 규칙에 맞춰 직접 수정하세요. 오류가 있는 문서의 저장은 허용하지 않습니다.

## 작성 완료 점검

- 메타데이터와 예시를 실제 프로젝트에 맞게 변경했는지 확인합니다.
- ID·상위·선행 참조와 순환 여부를 확인합니다.
- 작업의 완료 기준·담당자·상태·일정·공수를 확인합니다.
- Worktree에서 문서 오류가 없는지 확인합니다.

## 삭제와 번호 기록

앱에서 삭제할 때 하위 작업의 유지·삭제와 선행 참조 해제 여부를 선택합니다. 삭제한 번호를 다시 발급하지 않도록 메타데이터 next_task_number·next_milestone_number에 다음 번호를 보존합니다. 선택 항목이며 생략하면 현재 최대 번호 다음을 사용합니다. 값은 1 이상의 정수이며 앱이 보존한 값을 임의로 낮추거나 제거하지 마세요. 원본 ID·표시 설정·참조는 계속 정확한 문자열을 사용합니다.
