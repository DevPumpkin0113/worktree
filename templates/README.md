# WBS 공용 양식과 작성 규칙

## 사용 방법

1. 이 문서에서 작성 규칙을 확인합니다.
2. 옆의 [template.wbs](template.wbs)를 프로젝트 기획 폴더로 복사합니다.
3. 파일명을 프로젝트명.wbs로 바꿉니다. 예: planning/Worktree.wbs.
4. 프로젝트 정보와 예시 작업을 실제 내용으로 교체하고 Worktree에서 열어 확인합니다.

이 폴더는 공용 WBS 자료의 프로젝트 배포용 사본입니다. 기준 원본은 `resources/templates/wbs`입니다. template.wbs에는 작성에 필요한 항목만 두고 설명은 이 문서에서 관리합니다. 기존 프로젝트 문서는 중복 생성하지 않고 갱신합니다.

복사용 양식은 [template.wbs](template.wbs) 하나로 제공합니다. **`.wbs` 파일은 `.md`와 같은 Markdown 형식을 사용합니다.** 확장자만 다르며 일반 텍스트 편집기로 열고 수정할 수 있습니다. 내용은 이 문서의 WBS 작성 규칙을 따라야 합니다.

## 현재 지원 범위

- 기준 앱: Worktree 0.3.0, 문서 규격: schema_version 1.
- 현재 파서는 W001·W-001 및 문서 접두어가 지정된 ID와 정해진 작업 표의 열 이름·순서를 지원합니다.
- 문서의 id_prefix와 앱 전체 하이픈 표시 설정을 지원합니다. 원본 ID와 참조는 표시 설정으로 변경하지 않습니다.

## 작성 규칙

### 기본 형식

- 실제 WBS 파일은 반드시 `프로젝트명.wbs`로 저장합니다. 내부 내용은 Markdown이며, 예: `Worktree.wbs`입니다.

- `작업 목록` 바로 아래의 표만 시각화용 원본 데이터로 사용합니다. 다른 설명 표는 원본 데이터에 포함하지 않습니다.
- 한 행에 한 항목을 작성합니다. 표 셀에는 줄바꿈이나 중첩 목록을 사용하지 않습니다.
- 빈 값은 `-`로 통일합니다. 표 셀에 구분 문자 `|`가 필요하면 `&#124;`로 씁니다.
- 프로젝트 메타데이터의 `title`, `project_id`, `updated`와 문서 제목을 실제 값으로 교체합니다. `updated`는 마지막 수정일이며 `YYYY-MM-DD` 형식입니다.

### ID와 계층

- `ID`는 문서 내에서 고유하게 부여합니다. 기존 `W001` 형식을 유지할 수 있으며, `W-001` 및 문서 접두어가 지정된 ID도 지원합니다. 세 자리 이상 숫자를 허용합니다.
- 작업 이동이나 이름 변경 시에도 ID를 유지하고, 삭제한 ID를 재사용하지 않습니다.
- `상위 ID`는 부모 항목 하나의 ID입니다. 최상위 항목은 `-`로 씁니다.
- 계층은 ID 번호나 행 순서가 아닌 `상위 ID`로 결정합니다. 같은 부모 아래에서는 표의 행 순서를 표시 순서로 사용합니다.
- 부모 항목은 `group`이어야 합니다. 존재하지 않는 ID 참조, 자기 참조, 순환 계층은 허용하지 않습니다.

### 접두어와 ID 표시

- 메타데이터의 id_prefix는 선택 항목입니다. 생략하면 W, 지정 시 영문 대문자만 사용합니다. 예: id_prefix: OBS.
- 모든 유형에 같은 접두어를 사용합니다. 번호는 문서 전체에서 고유하게 부여하고 부모마다 다시 시작하지 않습니다.
- id_prefix: OBS 문서는 OBS001·OBS-001과 기존 W001·W-001을 읽습니다. 접두어가 없으면 W001·W-001만 허용합니다.
- 앱 설정의 ID 구분자 없음·하이픈으로 표시합니다. 앱 전체 설정이며 재실행 후에도 유지합니다. 문서에 구분자 메타데이터를 넣지 않습니다.
- 표시 설정과 접두어 메타데이터는 기존 ID·상위 ID·선행 작업을 자동 재작성하지 않습니다. 원본 참조는 정확히 일치해야 합니다.
- 같은 표시가 되는 작업은 원본 ID를 병기합니다. 예: W001 [W-001]. 두 작업을 합치지 않습니다.
- 실제 ID를 변경할 때는 부모와 선행 작업의 참조도 함께 수정합니다.

### 유형과 상태

| 필드 | 허용 값 | 의미 |
|---|---|---|
| 유형 | group | 하위 항목을 묶는 요약 항목 |
| 유형 | task | 실제 수행하는 작업. 하위 항목을 가질 수 없음 |
| 유형 | milestone | 승인·출시 등 특정 시점의 완료 사건. 하위 항목을 가질 수 없음 |
| 상태 | todo | 시작 전 |
| 상태 | doing | 진행 중 |
| 상태 | blocked | 진행을 막는 문제가 있음 |
| 상태 | done | 완료 기준을 충족함 |
| 상태 | auto | group 전용. 하위 항목에서 계산 |

- `group`은 반드시 하위 항목을 가지며, 상태를 `auto`로 입력합니다.
- `task`와 `milestone`에는 `todo`, `doing`, `blocked`, `done` 중 하나를 입력합니다.
- `담당자`는 책임 담당자 한 명을 적습니다. 아직 정해지지 않았으면 `-`로 씁니다.
- 각 `task`와 `milestone`의 `산출물 / 완료 기준`에는 완료 여부를 확인할 수 있는 조건을 적습니다.

### 일정과 선행 작업

- 날짜는 `YYYY-MM-DD`이며 시작일과 종료일을 모두 포함하는 달력 날짜입니다. 휴일·근무일 계산은 이 양식에서 다루지 않습니다.
- 일정 미정은 시작일·종료일 모두 `-`로 씁니다. 날짜가 있으면 시작일은 종료일보다 늦을 수 없습니다.
- `milestone`은 날짜를 입력할 때 시작일과 종료일을 같은 날짜로 씁니다.
- `선행 작업`에는 먼저 완료해야 하는 `task` 또는 `milestone`의 ID를 적습니다. 여러 개면 `W002, W003`처럼 쉼표로 구분합니다.
- 모든 선행 작업은 완료 후 시작(FS) 관계이며 지연일은 0입니다. 날짜만 사용하는 이 규격에서는 후속 작업을 선행 작업 종료일 다음 날 이후로 잡습니다.
- 같은 날 인계가 필요하면 이 규칙에 예외를 섞지 말고, 후속 규격에서 시간 단위를 추가합니다.
- 선행 작업은 없어도 됩니다. 존재하지 않는 ID 참조, 자기 참조, 순환 의존성은 허용하지 않습니다.
- `group`의 시작일·종료일·예상 공수·선행 작업은 모두 `-`로 입력합니다. 그룹 단위의 선행 조건은 실제로 영향을 받는 하위 작업에 연결합니다.

### 공수와 자동 집계

- `예상 공수(h)`는 작업에 드는 총 인시입니다. 예를 들어 두 명이 각각 4시간 일하면 8입니다. 일정 기간과는 다릅니다.
- `task`의 공수는 0보다 큰 숫자 또는 미정인 `-`로 씁니다. `milestone`의 공수는 0입니다.
- 그룹 일정은 모든 하위 말단 항목의 최소 시작일과 최대 종료일로 계산합니다. 일부 날짜가 미정이면 확정 일정으로 표시하지 않고 `일정 미정 포함`을 함께 표시합니다.
- 그룹 공수는 모든 하위 `task`의 공수를 합산합니다. 일부 공수가 미정이면 확정 총공수 대신 `입력된 공수 소계 + 미정 있음`으로 표시합니다.
- 그룹 상태는 하위 말단 항목을 기준으로 계산합니다. 모두 done이면 done, 하나라도 blocked이면 blocked, 모두 todo이면 todo, 나머지는 doing입니다.
- 공수 기준 진척도는 `done인 task의 예상 공수 합 / 전체 task의 예상 공수 합 × 100`입니다. 진행 중 작업의 부분 완료는 반영하지 않습니다.
- 공수가 미정인 task가 있거나 전체 공수 합이 0이면 공수 기준 진척도는 `산정 불가`로 표시합니다. milestone은 이 계산에서 제외하며 완료 개수를 별도로 표시합니다.
- 그룹과 그 하위 작업을 중복 합산하지 않습니다. 공수와 진척도는 항상 말단 task를 기준으로 계산합니다.

## 이슈 기록

blocked 작업에는 관련 ID와 함께 원인·해소 조건을 이슈 및 결정 사항에 기록합니다. 가정·미결정 사항은 확정된 결정과 구분합니다.

## 작성 완료 점검

- [ ] 프로젝트 메타데이터와 개요를 실제 내용으로 교체했다.
- [ ] 예시 작업을 실제 작업으로 교체했다.
- [ ] ID가 고유하며 상위 ID와 선행 작업 참조가 유효하다.
- [ ] 계층과 선행 작업에 순환 관계가 없다.
- [ ] 각 작업에 확인 가능한 완료 기준이 있다.
- [ ] 상태·날짜·공수에 작성 규칙을 적용했다.
- [ ] blocked 작업의 원인과 해소 조건을 기록했다.
